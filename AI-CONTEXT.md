## Rules for AI
1. Read `AI-CONTEXT.md`, then `projects/<X>/STATE.md`. Open code files only when the task needs them. To find code, read `scripts/codemap/CODEMAP.md` first (auto-generated functions/classes per file with line numbers; trust names, line numbers may lag; outside the MCP open `https://raw.githubusercontent.com/Shreyankkkkk/foundations/main/scripts/codemap/CODEMAP.md`).
2. Constants: never invent or hard-code. Every constant gets its calculation or measurement shown beside it, plus the source. Unmeasured = say so, mark it `PLACEHOLDER`; assumed = `ASSUMED`.
3. Code changes: give the code and say which file and where in it the change goes (he does not know the file layout by heart).
4. Be token-efficient: no padding.
5. Never run git commit/push. Shreyank commits. Before big edits, remind him to commit first.
6. Use today's date for every log line; never guess a date. If a date is unknown, write `date?`.
7. Naming: lowercase kebab-case, no spaces, `exercises` (not excercises). Do not create empty folders. Every folder with real content gets a README.
8. Public repo: no passwords, tokens, ID numbers, personal finances or private chat content.
9. Tokens: never read a whole `LOG.md` or journal file; read the last 3 lines only (tail). To append a line, use `edit_file` with the last line as `oldText` and that line plus the new line as `newText`. Never rewrite a whole file with `write_file` when a few lines change. Log only when he says `log it`, not after every message. To find or read part of a file, use `search_code` and `read_lines` (foundations-helper MCP) instead of opening whole files; if they are not listed, use the filesystem tools.
10. Teaching notes: when he asks to learn a term or topic, reply with the note content only, in one code block, template: Definition / Why it matters (for the project) / How it works / Example / 3 self-test questions. Max 200 words per term, plain language first. He pastes it into the right file himself: do not create, edit or re-read note files unless asked. Project notes go in `projects/<slug>/notes/`; reusable ones in `learning/<area>/notes/`.
11. If you cannot open a file or link, say so and ask him to paste it. Never claim to have read something you could not open. Outside the MCP, open raw file URLs (`raw.githubusercontent.com/...`), not GitHub directory pages.
12. `STATE.md` stays under about 150 lines and holds current truth only; history belongs in `LOG.md`. `projects/*/PORTABLE.md` is generated by `scripts/build_portable.py`: never edit it by hand.

## How to log (three layers, end of every session)
1. `journal/YYYY-MM.md`: append one line per session: `YYYY-MM-DD | learn/build/plan/research/achieve | what | files`.
2. Project work only: also append the detailed line to that project's `LOG.md`: `YYYY-MM-DD | what changed | why | evidence (file path or commit)`.
3. If the project's truth changed (a constant, a decision, a status): update its `STATE.md`. If a certificate was earned: add a row to `certificates/README.md`.
Newest at the bottom. One line per entry, however small. List changed files in the reply.
